# BoltUtil Payments for WooCommerce

Accept USDT in a USD WooCommerce store with BoltUtil Hosted Checkout. Customers choose a network at checkout, then pay the exact amount shown by BoltUtil to the merchant's configured receiving wallet. The plugin never asks for a wallet private key or recovery phrase.

**Current scope:** USDT on TRON (TRC20), Ethereum (ERC20), BNB Smart Chain (BEP20), Polygon PoS, and Solana. Base, USDC, and other assets are planned but are not available in this version.

> **Release status:** v0.4.21 is an early release. Order creation, Hosted Checkout redirect, repeated scheduled checks, and reconciliation of verified expired orders have been exercised on a test store. A real WooCommerce-originated blockchain payment followed by a production Webhook has not yet been verified end to end. Evaluate with a small amount before relying on it for live sales.

## What it does

- Adds a BoltUtil USDT payment option to classic WooCommerce checkout and Checkout Blocks.
- Shows only networks allowed in the plugin and backed by an active USDT receiving wallet in BoltUtil.
- Creates an idempotent LIVE payment through the BoltUtil Public Payment API and redirects the buyer to BoltUtil Hosted Checkout.
- Verifies signed Webhooks and rechecks payment status through the merchant's API key before marking a WooCommerce order paid.
- Keeps payment attempts and status in WooCommerce order details; supports a manual status recheck and scheduled reconciliation.
- Includes English source text and translations for Simplified Chinese, Spanish, Brazilian Portuguese, Russian, Vietnamese, Turkish, Japanese, Korean, Arabic, French, and Hindi. WordPress chooses the display language.

## Requirements and limitations

- WordPress 6.5+, PHP 7.4+, WooCommerce, HTTPS, and a WooCommerce store currency of **USD**.
- v0.4.21 declares support for the tested WooCommerce 11.1 line, HPOS, and Cart and Checkout Blocks. Earlier WooCommerce versions are outside the declared support window until tested.
- A BoltUtil account with a LIVE `bt_live_` API key, an active Webhook and its `whsec_` secret, and at least one active USDT receiving wallet for the networks you enable.
- BoltUtil is an external service. Read its [pricing](https://boltutil.com/pricing), [privacy policy](https://boltutil.com/privacy), and [terms](https://boltutil.com/terms). The free plan allows up to 30 newly created BoltUtil orders per server day.
- The USD order total is the invoice basis in USDT. This version does not quote or lock a live USD/USDT exchange rate. **Pay the exact USDT amount displayed on BoltUtil Hosted Checkout**; the wallet/network may charge a separate fee.
- Returning to the store is not proof of payment. Only verified payment status can complete the WooCommerce order. An expired attempt needs a new WooCommerce order.

## Configure in five steps

1. In WooCommerce, set the store currency to **USD** under **Settings → General**.
2. In [BoltUtil API Keys](https://boltutil.com/dashboard/api-keys), create a LIVE API key. In [BoltUtil Wallets](https://boltutil.com/dashboard/wallets), enable a USDT receiving address for each network you want to offer. You configure receiving *addresses* in BoltUtil; the plugin never needs a private key.
3. Open **WooCommerce → Settings → Payments → BoltUtil USDT**. Copy the store-specific Webhook URL shown at the top. In [BoltUtil Webhooks](https://boltutil.com/dashboard/webhooks), add that URL as an active Webhook for the **same merchant account** as the API key. Copy its `whsec_` secret.
4. Back in the WooCommerce gateway settings, enter the LIVE API key and Webhook secret, choose the allowed networks, enable BoltUtil USDT, and save. Saved secrets appear as masked hints; the password inputs themselves clear after saving. Leaving them blank on a later save retains the saved values.
5. Place an unpaid test-store order. Check the chosen network, BoltUtil redirect, receiving address, exact USDT amount, expiry, and return link. Complete a small real payment acceptance test before using the gateway for normal sales.

The plugin calls only `https://api.boltutil.com` for the payment API. There is no merchant-editable API destination.

## Order lifecycle

```text
WooCommerce checkout → BoltUtil payment → BoltUtil Hosted Checkout
    → blockchain confirmation → signed Webhook → merchant-scoped status read
    → WooCommerce payment completion
```

A buyer's browser return does not mark an order paid. A valid completion event is checked for signature, freshness, matching order/payment/network/amount, and a confirmed API status. Event IDs are claimed in a database table to prevent duplicate fulfillment. Expired, failed, cancelled, underpaid, and unusual transfers require the merchant to review the BoltUtil dashboard and WooCommerce order notes.
