## How WordPress selects the interface language

- Set the storefront language under **Settings → General → Site Language**.
- Administrators can choose their preferred admin language under **Users → Profile → Language**.
- The plugin uses standard WordPress translation functions and the `boltutil-payments-for-woocommerce` text domain. Unsupported locales fall back to English.
- A multilingual-store plugin must provide the corresponding WordPress/customer locale; this plugin does not install a language switcher or translate the whole store.
- Merchant-written payment titles, descriptions, product copy and policies do **not** translate automatically. Maintain them through your store's normal multilingual-content tools.
- Hosted Checkout is a separate BoltUtil service surface, with its own locale handling and wallet availability. The WordPress PO/MO catalogs do not translate a customer's wallet app.

## Updating translations with a release

1. Update English source strings and the POT together.
2. Update all eleven PO files and compile their MO files. Preserve placeholders and the current plugin version in catalog metadata.
3. Run `msgfmt --check` for every PO and `python3 tools/check-distribution.py`. Distribution checks require all runtime PHP strings in every MO catalog.
4. Update version links, requirements, route names and early-release status in every translated introduction. Keep token variants such as Bridged USDT and Binance-Peg USDC explicit.
5. Update the main README and `.github/RELEASE_NOTES.md` before packaging.

## Public images

Shared checkout screenshots use English, with captions and explanations in the relevant documentation. English and Simplified Chinese listing banners are provided. The WordPress.org locale-specific banner naming follows the [official plugin assets specification](https://developer.wordpress.org/plugins/wordpress-org/plugin-assets/); no directory listing or approval is implied.

The screenshots show real interface states. They must not include private keys, API keys, Webhook secrets, personal customer details or checkout bearer tokens. Do not label a UI screenshot as evidence of a completed real payment.
